## 📝 Challenge Description

A program stores user input in a fixed-size buffer. Send more data than expected → overflow into adjacent memory.

---

## 🔍 What Is a Buffer Overflow?

A buffer is a fixed-size region of memory allocated to hold data (e.g., a string). When you write more data than the buffer can hold, the excess spills over into neighboring memory.

In this challenge, the program has a buffer of 16 characters and a single byte flag `authenticated` right next to it in memory. Overflowing the buffer overwrites that flag.

---

## 🛠️ Steps to Solve

### Step 1 — Understand the Program

The vulnerable program:
- Allocates a 16-byte buffer
- Has an `authenticated` variable set to `0` (False)
- Reads user input into the buffer with `gets()` or similar unbounded function
- Prints "Authenticated: 1" if the flag is non-zero

### Step 2 — Send 32 'A' Characters

```
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
```

Why 32? The buffer is 16 bytes, and there is likely padding between the buffer and the `authenticated` flag. Sending 32 bytes overflows past the buffer and overwrites the flag in memory.

### Step 3 — Observe the Result

The program prints: `Authenticated: 1`

The `authenticated` variable was overwritten from `0` to `0x41414141` (AAAA in hex), which is non-zero, so the authentication check passes.

### Step 4 — Get the Flag

Without any password, you've bypassed authentication entirely. The flag is revealed.

## 💡 Key Learnings

1. **Never trust user input size** — always validate and bounds-check.
2. **Fixed-size buffers + unbounded input = overflow.** Use `fgets()`, `scanf()` with width limits, or safer alternatives.
3. **Modern systems have mitigations** — stack canaries, ASLR, NX/DEP, and stack cookies help prevent exploitation, but this challenge shows the classic vulnerable pattern.
4. **In CTFs, look for the pattern** — if you can overflow, overflow past the flag variable.

---

## 🛡️ Mitigation (Real World)

- **Use safe functions**: `fgets()` instead of `gets()`, `strncpy()` instead of `strcpy()`
- **Stack canaries**: Detect overwrites before function return
- **ASLR**: Randomize memory addresses
- **DEP/NX**: Mark stack as non-executable
- **Language choice**: Rust/Go have built-in bounds checking
